## Before you begin

You only need a few basics to get started: a clear page title, one or two sections you want to document first, and a place to store your drafts. If you plan to publish immediately, make sure your workspace settings and access permissions are already in place.

## Quick setup

<Steps>
  <Step title="Create your workspace" icon="folder-plus">
    Open your documentation project and create a home for your content. Give the workspace a name that matches your team or product so people can find it easily.
  </Step>
  <Step title="Add your first page" icon="file-text">
    Create a new page called Getting Started or Overview. Keep the first version short and focused on one clear outcome.
  </Step>
  <Step title="Add sections" icon="layout">
    Break the page into readable sections such as Overview, Setup, and Next Steps. Use headings to help readers scan the page quickly.
  </Step>
  <Step title="Publish your content" icon="rocket">
    Review the page, fix formatting, and publish when you are ready. If your editor supports drafts, use them to iterate before the final release.
  </Step>
</Steps>

## Basic editor workflow

The simplest workflow is draft, review, and publish. Write the page in small sections, preview it often, and adjust the wording so it is easy to understand. This keeps your documentation consistent and reduces the chance of missing important details.

<CodeGroup tabs="Markdown,HTML,JSON">
  ```markdown
  ## Getting Started

  Welcome to the project docs.

  ### What you will learn

  - How to create a page
  - How to organize sections
  - How to publish your work
  ```

  ```html
  <h2>Getting Started</h2>
  <p>Welcome to the project docs.</p>
  <h3>What you will learn</h3>
  <ul>
    <li>How to create a page</li>
    <li>How to organize sections</li>
    <li>How to publish your work</li>
  </ul>
  ```

  ```json
  {
    "title": "Getting Started",
    "status": "draft",
    "published": false
  }
  ```
</CodeGroup>

## Choose a structure

Use a repeatable structure so readers always know where to look. A good first page usually includes a short overview, a practical example, and a next step that tells the reader what to do next.

<Tabs>
  <Tab title="Recommended structure" icon="check-circle">
    Keep your page focused on the most useful first task. For example, explain how to create a page, then show how to organize it, and finish by publishing it.
  </Tab>
  <Tab title="Minimal structure" icon="file">
    If you want the shortest possible version, use a title, one short paragraph, and a single example section. You can expand it later.
  </Tab>
  <Tab title="Expanded structure" icon="layers">
    Add an introduction, setup steps, examples, and a short FAQ when you need more detail for new users.
  </Tab>
</Tabs>

## Publishing checklist

Before you publish, confirm that the page uses clear headings, accurate examples, and a consistent tone. Make sure links work, code blocks are complete, and the page answers the question a new reader is most likely to ask.

1. Check that the page title is specific.
2. Confirm that each section has a purpose.
3. Review examples for accuracy.
4. Make sure the page reads well on its own.
5. Publish and revisit it after feedback.

<Callout kind="tip">

Keep your first version simple. You can always add screenshots, diagrams, and advanced notes after the core workflow is working well.

</Callout>
